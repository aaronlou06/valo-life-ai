Create one reusable empty-state component used everywhere below. It should render:

A small icon or light illustration drawn from the existing warm palette (terracotta, sage, sand, etc.).
A short headline.
One line of supporting subtext.
A single primary call-to-action button.
An optional secondary/alternate action line where noted.

Keep it visually quiet and intentional — it should feel like part of the design system, not a placeholder. The same component handles both true first-run and any later moment a section has no data.
Loading vs empty logic (the part that currently reads as broken)
Today, genuinely-empty sections appear to sit on a skeleton that never resolves. For every section below, ensure three distinct states:

Loading — a brief skeleton only while a data request is genuinely in flight.
Empty — the request has resolved with no data; render the shared empty-state component.
Populated — render the real content.

A resolved-but-empty result must land on the empty state, never a persistent skeleton.

Voice
Copy above is the recommended starting voice — warm, first-person Valo, consistent with "Nothing you tell me disappears. It all compounds." Treat the exact wording as adjustable; keep the tone.
Edge cases
Seeded integrations partially populate. Because state is decided per section, a tab can be partly populated (e.g., calendar has events, Health has some HealthKit metrics) while other sections show empties. Only truly-empty sections show the empty state.
No name / onboarding skipped. The greeting falls back to a warm neutral greeting without a name.
Returning user clears their data. Someone who deletes all their habits (or has no goals again) sees the same empty state — these are not first-run-only.
Acceptance criteria
A freshly onboarded account with no check-ins shows warm, Valo-voiced empty states across all four tabs, with no skeletons that read as broken.
Home shows the From Valo welcome variant and hides empty At-a-Glance cards entirely.
Sections backed by seeded data (calendar events, available HealthKit metrics) render populated, not empty.
Each empty state has exactly one primary CTA that routes correctly: check-in launcher, New Event flow, add goal, add habit.
The Life Balance radar shows a ghost baseline plus prompt, never a blank or broken chart.
All empty states reuse the single shared component.
A returning user who clears data sees the same empty states, not just first-run users.
