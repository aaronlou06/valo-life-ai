The model string is wrong. claude-opus-4-5 isn't a current model — it's stale. You already have a configured Anthropic client (lib/integrations-anthropic-ai/src/client.ts is in your relevant files), so point the generation call at whatever model that client is configured with rather than hardcoding a string in the route. If you do pin one, the current lineup is Opus 4.8 (claude-opus-4-8), Sonnet 4.6 (claude-sonnet-4-6), Haiku 4.5. And for this task, Opus is overkill — the model only proposes recipes and rough ingredient macros; the backend owns the arithmetic and snaps portions. Sonnet 4.6 handles constrained recipe JSON easily and costs less. Default to Sonnet; only reach for Opus if recipe quality disappoints.
Allergen filtering can't be a literal string match. "Rejects any ingredient matching the allergen list" is the one place a bug is dangerous rather than just inaccurate. A naive match misses derivatives — a peanut allergy has to catch "peanut oil," a milk allergy has to catch whey, casein, butter, ghee; tree-nut, soy, shellfish all have the same problem. Make the exclusion derivative-aware: maintain an allergen→derivatives map the validator checks against, and have the generation prompt explicitly flag any ingredient derived from a listed allergen. Belt and suspenders, because it's a health filter.
